# Trubot product direction

Updated 2026-10-17 after Joe's explicit steering: stop treating incremental memory
repairs as the main product roadmap. Build an adaptive league character that can
understand recent discussions, gather relevant context and share worthwhile visuals.

1. First visual skill: U.P. aurora opportunities followed by a next-morning generated
   scene. H89/2.29.0 checks observed space weather, overlapping local sky conditions,
   darkness and conversation timing. Generated origin stays clear; no invented sighting.
2. Bigger context architecture: recent group-discussion episodes, peers/replies/threads
   and inspected pixels where relevant, followed by selectively loaded tools/skills.
   Current recent target-message ingestion works; complete discussion memory does not.
3. More visual life: varied U.P. aurora scenes and short natural captions, then
   generated trail-camera wildlife. Validate sharing timing, actual pixels and cost.
4. Abstract personality, warmth and amplified humor: return to independently useful,
   qualified episode patterns. Avoid repeating rejected populations and tiny literal
   quote/date patches without a material defect.

Each increment needs falsifiable acceptance, held-out or realistic scenarios,
actual private Discord tests, protected CI and verified immutable deployment.
Architecture rewrites remain available when matched evidence supports them.
The graph/retrieval/learning/spending foundations already exist. Their existence is
not evidence of human fidelity or engagement gains. Public data and synthetic scenes
must never become evidence about Andrew's actual habits, actions or beliefs.

Preserve existing privacy/source lifecycle, runtime channel scope, bot identity,
20USD/month cap and six standalone local01/05/09/13/17/21Sol/xhigh runs. Scheduled
morning images are specifically authorized; normal ambient participation stays intact.
