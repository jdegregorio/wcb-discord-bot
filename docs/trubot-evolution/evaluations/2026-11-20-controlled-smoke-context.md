## Implementation and operational use

Default `--context live` observes the complete bounded generation-history packet
and stores only row count/SHA256. Explicit `--context isolated` returns no rows in
the auxiliary process, for its exact authenticated private probe/channel only.
The current focus, target fetch, memory/source rechecks, provider and real Discord
send/readback remain in production handlers. This is a deliberate history harness
substitution, not fully unmodified end-to-end or owner/main-gateway proof. Finally
restores the collector even on cancellation; no production process is patched.
A transport pass also requires observed history collection. Retained attempts bind
the mode before network work; old receipts are live-only and never replay.

Use a unique never-reused run ID per mode and retain the same fixed case:
`python scripts/discord_smoke.py run --run-id <unique> --case care --context isolated`.
Run in the existing app-scoped environment via the authorized operator path.
`status` requires the matching mode. Existing0700/0600, seven-day manual retention
and withdrawal cleanup apply. Do not delete uncertain receipts to retry or infer
quality from hashes. Private app receipts use daily-20261120-0500-*; no source or
answer prose, personal observations or pixels enter retained artifacts/Git.
