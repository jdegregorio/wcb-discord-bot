The candidate adds 19 deterministic regression cases. All pass, including concurrent
exclusive claims, replay of pending/failed/completed attempts, ambiguous probe sends,
cancellation after a real-send return, receipt-write failure without handler fallback,
unsafe paths, wrong scope, withdrawal, readiness and sanitized CLI errors. Initial
full-suite execution exposes three diagnostics failures because the CLI test leaves
logging disabled. Main now restores the caller's logging level in a finally block;
35 combined runner/diagnostic cases pass. All six final feature gates pass: locked

and wheel/sdist. The initial sandbox cache failures and shared-log collision during
H129 reconciliation are not product failures or counted gates.

Two fresh candidate-script executions each produce exactly one actual bot answer
in the verified private development channel, and each exact-ID repeat returns the
identical completed receipt. The first replay additionally preserves receipt bytes
and mtime and observes no change in the entire app's provider-attempt count or
estimated spend. The final script's fresh repeat is also identical. Each confirms
rejected development intake, unchanged learning-message count, isolated readiness
and closed auxiliary client. The script observes the real HTTP send and fetches that
exact answer ID. It never guesses an answer from concurrent channel history.
No human question, owner reaction, main gateway, newly learned trait or improved
character/humor semantics is claimed. Transport-only result remains explicit.

Records live in the existing private app-volume smoke-tests tree, 0700/0600,
content-free and governed by seven-day manual retention/withdrawal cleanup. An
interrupted claim stays consumed even without a returned message ID; terminal
output is not authoritative. The installed discord.py source supplies/enforces
one nonce across its internal send retries; process-level idempotence comes from
the separate durable claim. This is not a promise of exactly-once network delivery.
No source/graph state, checkpoints, runtime bytes/config, automatic job, release,
image, deployment or rollback is changed. Protected CI/merge, exact merged checks,
final health, immutable production reference and final spending are recorded below
when verified.
